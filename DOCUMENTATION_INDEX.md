### Documentation Best Practices

1. **Update as you go** - Don't leave docs for later
2. **Link generously** - Help readers find related info
3. **Use examples** - Code examples > long explanations
4. **Keep it current** - Outdated docs worse than no docs
5. **Think about audience** - Who will read this?

---

## 🎯 Documentation Quality Checklist

**Good documentation should:**
- [ ] Have a clear purpose stated at the top
- [ ] Be dated or versioned
- [ ] Link to related documents
- [ ] Include code examples where relevant
- [ ] Be organized with clear headings
- [ ] Have a table of contents for long docs
- [ ] Be written in active voice
- [ ] Be tested (commands actually work)

## 🤝 Contributing to Documentation

### Adding New Documentation

1. Create the file with `.md` extension
2. Add standard header:
   ```markdown
   # Title

   **Purpose:** What this doc is for
   **Audience:** Who should read this
   **Last Updated:** Date
   ```
3. Update [DOCUMENTATION_INDEX.md](./DOCUMENTATION_INDEX.md) (this file)
4. Link from relevant docs (README, CURRENT_STATUS, etc.)
5. Test all commands/code examples

### Improving Existing Documentation

1. Check if info is current
2. Make updates
3. Update "Last Updated" date
4. Test any changed commands
5. Commit with clear message: `docs: Update [filename] with [changes]`
